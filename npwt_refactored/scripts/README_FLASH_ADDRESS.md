# Flash地址安全计算方法

## 问题背景

当代码增加新功能时，程序代码会增长，如果Flash存储地址设置不当，可能会：
1. 覆盖程序代码，导致设备无法启动
2. 覆盖常量数据（如LOGO图片），导致显示异常

## 解决方案

### 方法1：使用自动计算工具（推荐）

使用提供的Python脚本自动计算安全的Flash地址：

```bash
# 使用默认设置（2KB安全边距）
python3 scripts/calculate_safe_flash_address.py

# 指定map文件和安全边距
python3 scripts/calculate_safe_flash_address.py NWPT_VR.X/dist/default/production/NWPT_VR.X.production.map 2
```

**工作流程：**
1. 编译项目，生成map文件
2. 运行脚本，自动提取程序代码最大结束地址
3. 脚本计算安全地址（程序代码结束地址 + 安全边距，64字节对齐）
4. 验证地址是否在安全范围内
5. 更新 `HAL/Inc/hal_flash.h` 中的 `HAL_FLASH_CONFIG_ADDRESS`

### 方法2：手动计算

#### 步骤1：编译项目
```bash
# 在MPLAB X IDE中编译，或使用make命令
make -f nbproject/Makefile-default.mk
```

#### 步骤2：查找map文件
map文件位置：`NWPT_VR.X/dist/default/production/NWPT_VR.X.production.map`

#### 步骤3：查找程序代码最大结束地址
在map文件中查找CODE段信息，格式如下：
```
text59                         00C4E2  0000DA  00C5BC      6271       0  CODE
intcode                        000008  00C4D9  00C4E1         4       0  CODE
```

找到最大的结束地址（第4列），例如：`0xC5BC`

#### 步骤4：计算安全地址
```
安全地址 = ((最大代码结束地址 + 安全边距 + 63) // 64) * 64
```

**参数说明：**
- 最大代码结束地址：从map文件获取（例如：0xC5BB，即0xC5BC-1）
- 安全边距：推荐1KB-2KB（为未来代码增长预留空间）
- 64：Flash块对齐大小

**示例：**
```
最大代码结束地址：0xC5BB (50619)
安全边距：2KB (2048字节)
目标地址：0xC5BB + 2048 = 0xCDBB (52667)
对齐后：((0xCDBB + 63) // 64) * 64 = 0xCDC0 (52928)
```

#### 步骤5：验证地址
确保地址满足以下条件：
1. ✓ 在未使用CODE区域内：`0xC5BC <= 地址 <= 0xE13D`
2. ✓ 不在常量数据范围内：`地址 < 0xE13E`
3. ✓ 64字节对齐：`地址 % 64 == 0`

#### 步骤6：更新代码
在 `HAL/Inc/hal_flash.h` 中更新：
```c
#define HAL_FLASH_CONFIG_ADDRESS    0xCDC0U    // 从脚本计算得出
```

## 安全边距建议

| 场景 | 推荐安全边距 | 说明 |
|------|------------|------|
| 代码基本稳定 | 1KB | 为小幅功能增加预留空间 |
| 代码持续开发 | 2KB | 为中等规模功能增加预留空间 |
| 代码大幅重构 | 4KB | 为大规模功能增加预留空间 |

## 地址范围限制

根据map文件分析，Flash地址必须满足：

```
0xC5BC <= 地址 <= 0xE13D
```

- **最小地址**：`0xC5BC`（未使用CODE区域开始）
- **最大地址**：`0xE13D`（未使用CODE区域结束）
- **常量数据开始**：`0xE13E`（不能超过此地址）

## 开发流程

### 每次添加新功能后：

1. **编译项目**
   ```bash
   # 在MPLAB X IDE中编译，或使用make命令
   ```

2. **运行计算脚本**
   ```bash
   python3 scripts/calculate_safe_flash_address.py
   ```

3. **检查输出**
   - 如果地址验证通过，更新 `HAL_FLASH_CONFIG_ADDRESS`
   - 如果地址验证失败，减小安全边距或检查代码大小

4. **测试验证**
   - 编译并下载程序
   - 关机保存参数
   - 再次开机，检查是否正常

### 如果地址超出范围：

如果计算出的地址超出 `0xE13D`，说明：
1. 代码增长过快，需要优化代码大小
2. 安全边距设置过大，可以适当减小
3. 考虑使用其他存储方案（如EEPROM）

## 注意事项

1. **地址对齐**：Flash地址必须是64字节对齐
2. **定期检查**：每次添加新功能后都要重新计算
3. **保留余量**：不要使用到 `0xE13D`，为未来预留空间
4. **版本控制**：将计算出的地址记录在Git提交信息中
